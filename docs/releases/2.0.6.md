## Crosshair Z 2.0.6

Reliability and performance release from a full review of 2.0.5. No new features; config, share codes and rendered crosshairs are unchanged.

### In game

- Holding a hotkey (show/hide, next/previous, settings or a crosshair's own hotkey) fires once instead of repeating with keyboard auto-repeat. Move hotkeys still repeat while held.
- The overlay redraws only when something changes and does no animation work while the crosshair is hidden. It no longer re-raises itself on every animation frame.
- Mouse buttons are no longer polled while the crosshair is switched off, and a right-click hide/switch state ends when you switch crosshairs or turn the crosshair off and on.
- The background runtime uses 2 worker threads instead of one per CPU core.
- A crosshair that failed to render is tried again the next time it is needed once a wait has passed (1 minute, doubling up to 15 minutes), instead of showing the fallback dot until the next restart.
- The sprite disk cache keeps 512 rendered crosshairs instead of 64 and never removes ones in use, so more crosshairs show right after a restart without re-rendering.

### Your saved crosshairs

- If `config.json` cannot be read at startup (for example while a backup or antivirus tool locks it), the app retries, then runs without saving for that session and shows a banner in settings, instead of replacing your library with defaults.
- Saves are flushed to disk before `config.json` is replaced, and failed saves are retried.
- A `config.json.bak` copy is kept and used when `config.json` is missing or damaged. A `config.json.lossy-<time>` copy is kept before loading a config this version would partly drop, such as one written by a newer version.

### Settings

- Settings no longer get stuck redrawing when many drawings, images or SVG-rendered designs (such as imported Crosshair X crosshairs) are shown, and library and Crosshair X cards no longer stay blank.
- Letter hotkeys are recorded as labelled on your keyboard layout (Z and Y on German layouts); numpad operators and the Windows key are recorded correctly.
- Discover no longer adds a copy of a crosshair you already saved.
- Undo right after an edit steps back one change and Redo restores it, the undo history is kept when the same crosshair reloads, dragging follows the cursor at every size, wheel zoom no longer gets stuck, and editing an imported drawing no longer crops it.
- The size and position sliders no longer jump back while you drag them, and a failed import keeps the pasted code in the field.
- Share codes longer than 10,000 characters are no longer cut off when copied or pasted (the limit is now 2,000,000); copying confirms success, longer codes are rejected with a clear message, and a damaged profile no longer blanks the window.

### System

- File logging recovers after temporary write errors, and log lines from two processes no longer merge.
- Autostart cleanup only removes Crosshair Z entries.
- DLLs the executable imports are loaded from System32 only, so a planted copy of one of them next to the exe is not picked up.
- Single-instance handover only quits after the new instance received its answer and recovers when its pipe fails; update downloads are synced to disk, cancelled after 10 minutes in total and not deleted while still running, and a missing release endpoint is logged as a warning.

Validation: 150 Rust unit tests, the golden sprite test and 48 JavaScript tests pass. The isolated smoke test passes all 8 checks (5.3 MB private working set). This build is unsigned; Windows SmartScreen may warn.
